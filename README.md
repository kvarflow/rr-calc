## Small-screen layout

On small screens (up to 640 CSS pixels on the shorter side), such as the AYN Thor's 3.92"
1240 × 1080 lower screen (537 × 468 in Chrome, at 2.31× scaling), the calculator switches to tabs:

- **Battle**: both sides' moves and the detailed result, then your team and the trainer's as
  cards. Tap one to load it, drag your team into order, mark the trainer's Pokémon KO'd and step
  to the previous or next trainer (Next stands out once his whole team is KO'd). Double-tap a
  move to make it a crit (it shows CRIT), and again to undo. Each of the foe's moves shows the
  chance the trainer's AI picks it (see Trainer AI below); the likeliest has a red stripe, tagged
  KO when it can knock you out from your current HP. **Fainted** on your
  team's card marks the Pokémon in Pokémon 1 as fallen (to the one it faces), and each KO you mark
  is credited to it: KO counts show on your cards.
- **You** and **Foe**: each Pokémon on one screen: the stats beside nature, ability, item and
  status, then a slim HP bar and the moves. Type, forme, gender and level come from the save, so
  they only show with the whole table (Base / IVs / EVs).
- **Advanced**: the trainer (his starter-dependent team, Professor Oak's new run), the run's
  progress bars and **This run** (top fraggers, the fallen, your personal best and past runs,
  kept per mode; a run is recorded when Professor Oak ends it, and the best is the one that beat
  the most trainers, then kept the most Pokémon standing), then the field in sections: battle,
  weather, terrain, rooms, each side's conditions and Export. A `.sav` Pokémon is known by its
  personality value, so its KOs and fainting survive re-importing however it was moved.
- **Box**, **Wild** (below) and **More**: import and export, Range Compare, then the settings,
  with sliding selectors for the mode and the notation, the accent color (red unless you pick
  another), the text size and Install.

Swipe left or right to change tabs. Battle recalculates as you type (on-screen keyboards send no
key presses), once per change.

### Install as an app

`manifest.webmanifest` makes the calculator installable: Chrome on the Thor or a phone offers
Install (More → App), or use ⋮ → Add to Home screen. It opens full screen, works offline and
starts on the mode you used last. For an APK, [PWABuilder](https://www.pwabuilder.com/) can
package the published site as an Android app (a Trusted Web Activity) that keeps updating with
the site.

Phones get it too: held upright, the tabs sit at the bottom and the You / Foe details go under
the stats; held sideways, it is laid out like the Thor. Layout in More's settings forces it on or
off on any device, and the screen size the page sees is shown beside the credits.

The small-screen layout (the Thor and phones, not desktop) also has a **Wild** tab: every location's wild Pokémon by method (grass or cave, surfing, Rock Smash and each
rod), in the order you reach them (as in the locations sheet, then the post-game and the Sevii Islands), by day (04:00–16:59) and night (17:00–03:59), with levels and chances. It opens on the current
trainer's location and ticks species already in your box. `src/js/data/encounters.js` is read from
the game's encounter tables (the night table, the day table and the default one they fall back
to) by `import/radical-red-encounters.js`; floor and area names come from
[pret/pokefirered](https://github.com/pret/pokefirered)'s map names, and for the areas Radical Red
added (Pokémon Tower 8F and 9F, Rock Tunnel's post-game area...) from the community's Pokémon
Locations & Raid Dens v4.1 sheet. Checked against that sheet, 235 of its 242 Kanto tables match the
game exactly; the rest differ in Pumpkaboo's sizes (named here by the game's stats), a few
Seafoam B4F levels, and Fuchsia City's fishing and surfing, which the game still has at FireRed's
levels (as it does Route 4's, where a save's Old Rod Magikarp was caught at FireRed's Lv 5).

Grass and caves sit on the left, beside fishing and then surfing on the right. Ticking **Nuzlocke**
(per mode) allows one encounter per location, counting a location as the game names it (all of
Mt. Moon's floors are one): a `.sav` import fills in where each of your Pokémon was caught, from the
met location the save keeps for each one; tapping a Pokémon, or "Missed it", uses up a location by
hand, and Professor Oak's new run clears them. With it ticked, the dupes clause blacks out anything
in the evolution family of a Pokémon you have caught or have in your box (a Furret from Route 2
blacks out Sentret on later routes), and it cannot be a location's encounter. The families come
from the game's own evolution table; a species' sizes count as one, its regional forms do not.

## Trainer AI

On Battle (Normal and Hardcore Mode), each of the foe's moves shows how often the trainer's AI
picks it. `src/js/trainer_ai.js` ports the move choice of Complete Fire Red Upgrade's battle AI
(`src/Battle_AI`), which Radical Red is built on, for single battles:

- Every move starts at 100. *Negatives* (every trainer) takes points off moves that would fail
  or waste the turn: Thunder Wave into a Ground type, Recover at full HP, a stat boost at +6.
  *Positives* (the bosses and the other trainers flagged smart) adds points for a KO that goes
  first (+9), a slower KO, the strongest move (+2), a status move or set-up when it suits the
  Pokémon's fighting style (worked out from its four moves, as the game does), and more.
- The game reads its damage as one number, the calculator's highest roll × 0.93, and predicts
  your move first (with the smart scoring) to judge speed order, Sucker Punch and the like.
- The highest score wins, ties at random. The AI's own rolls (a 50% crit, four random numbers it
  draws each turn, coin flips between equally strong moves, your predicted move when it is a tie)
  are enumerated exactly, so the percentages are exact for what the calculator knows.
- Each trainer's AI flags, and every move's effect, accuracy and secondary chance, come from the
  game (`import/radical-red-trainers/ai_flags.js` writes `src/js/data/trainer_ai.js` from the
  ROM). Required trainers not found in the ROM's tables use the smart AI, optional ones the basic.

What it cannot know is assumed: no moves used yet this battle (no Protect last turn, no Choice
lock), the foe's Pokémon has just come in when it is at full HP (Fake Out), the foe can switch
while it has a Pokémon left, and no Substitutes. Switching and item use are not modelled. Set the
field (weather, screens, hazards, Trick Room) and both Pokémon's HP and status as they are.

## Offline

Once opened online, the calculator works with no connection: a service worker (`src/sw.js`)
saves every page and the files they load, and `node build` writes that list and a version
into it, so each new build replaces the saved copy. Pages are fetched online first when there
is a connection, so updates still arrive. Sprites are saved as they are first seen.

## Pokémon from your save

A Pokémon imported from a `.sav` keeps the save's type, base stats, IVs, EVs, level and ability,
locked so they cannot drift from the game ("Edit anyway" unlocks them). Stat stages are − / +
buttons, and nature (it can be changed in the game), item, status, current HP and moves stay
editable. Matchup color coding is on
unless you turn it off.

## `@smogon/calc`

The `@smogon/calc` package powers the UI, providing a programmatic interface for computing damage
ranges. This subpackage contains code that will run on both the server or browser and can be used
as a building block for alternative UIs or applications.

### Installation

```sh
$ npm install @smogon/calc
```

Alternatively, as [detailed below](#browser), if you are using `@smogon/calc` in the browser and want
a convenient way to get started, simply depend on a transpiled and minified version via [unpkg][5]:

```html
<script src="https://unpkg.com/@smogon/calc/dist/data/production.min.js"></script>
<script src="https://unpkg.com/@smogon/calc"></script>
```

*In this example, the `@smogon/calc/data` code is included as well to fulfill the calc's data
layer requirement. Alternatively, a more fully-featured data layer such as [`@pkmn/data`][9] may
be used instead, see below.*

### Usage

`@smogon/calc` exports all of the data types required to perform a calculation. The `calculate`
methods require:

- a `Generation` that contains information about which damage formula mechanics to apply and where
  all of the data about the generation can be found.
- attacker and defender `Pokemon` (note: only relevant attributes are required, everything else
  should have sensible defaults). The `Pokemon` constructor also requires a `Generation` to provide
  the Pokémon's data for the generation.
- the `Move` being used by the attacker (which also requires a `Generation` argument to scope the
  move data to the particular generation).
- (optionally) a `Field` object containing information about the state of each `Side`.

`calculate` returns a `Result` object that contains methods for fetching damage rolls, ranges,
descriptions, recoil/drain information, etc.

```ts
import {calculate, Generations, Pokemon, Move} from '@smogon/calc';

const gen = Generations.get(5); // alternatively: const gen = 5;
const result = calculate(
  gen,
  new Pokemon(gen, 'Gengar', {
    item: 'Choice Specs',
    nature: 'Timid',
    evs: {spa: 252},
    boosts: {spa: 1},
  }),
  new Pokemon(gen, 'Chansey', {
    item: 'Eviolite',
    nature: 'Calm',
    evs: {hp: 252, spd: 252},
  }),
  new Move(gen, 'Focus Blast')
);
```

`@smogon/calc` comes packaged with all of the data required for damage calculation - by default, it
exposes this via its `Generations` object from `@smogon/calc/data`. As a shortcut, the `Generation`
argument required by `calculate`, `Pokemon`, `Move` can instead simply be the generation *number*
(eg. `5`), and it will handle getting that generations `Generation` object behind the scenes from
the data layer it ships with.

**The data in `calc/data` must be kept in sync with Pokémon Showdown. If there is an issue with the
calc's data, please fix it in the simulator first.** In general, you should probably not be
making manual edits to any of the data files, and in the future, they are likely to be generated
programmatically.

In some advanced use cases, you may wish to use a different data layer with the calculator. The
`@smogon/calc/adaptable` entry point can be used with any data layer that implements the calc's
`Generations` interface. This interface is a subset of [`@pkmn/data`][9]'s `Generations` interface,
so `@pkmn/data` (which contains all competitively relevant data from Pokémon Showdown) can be used
with the adaptable entry point for applications which want to avoid having two separate sets of the
same data shipped to users.

```ts
import {Dex} from '@pkmn/dex';
import {Generations} from '@pkmn/data';
import {calculate, Pokemon, Move, Field} from '@smogon/calc/adaptable';

const gens = new Generations(Dex);

const gen = gens.get(1);
const result = calculate(
  gen,
  new Pokemon(gen, 'Gengar'),
  new Pokemon(gen, 'Vulpix'),
  new Move(gen, 'Surf'),
  new Field({defenderSide: {isLightScreen: true}})
);
```

### Browser

The recommended way of using `@smogon/calc` in a web browser is to **configure your bundler**
([Webpack][6], [Rollup][7], [Parcel][8], etc) to minimize it and package it with the rest of your
application. If you do not use a bundler, a convenience `production.min.js` is included in the
package. You simply need to depend on `./node_modules/@smogon/calc/production.min.js` in a `script`
tag (which is what the unpkg shortcut above is doing), after which **`calc` will be
accessible as a global.** You must also have a `Generations` implementation provided, you can either
depend on the calculator's data layer by depending on
`./node_modules/@smogon/calc/data/production.min.js` (or `@smogon/calc/data` via unpkg), or you can
use an alternative data layer such as [`@pkmn/data`][9]. You must load your data layer
**before** loading the calc:

```html
<script src="./node_modules/@smogon/calc/data/production.min.js"></script>
<script src="./node_modules/@smogon/calc/production.min.js"></script>
```

## UI

The [UI layer][2] is currently is written in vanilla JavaScript and HTML. To view the UI locally you
first must install dependencies by running `npm install` at the top level and without `calc/`. This
should create a `node_modules/` folder under both the root directory and under `calc/`:

```sh
$ npm install
$ cd calc && npm install
```

Next, run `node build` from the root directory of your clone of this repository. This should
run `npm run compile` in the `calc/` subdirectory to compile the `@smogon/calc` package from
TypeScript to JavaScript that can be run in the browser, and then compile the 'templated' HTML
and copy everything into the top-level `dist/` folder. To then view the UI, open `dist/index.html` -
simply double-clicking on the file from your operating system's file manager UI should open it in
your default browser.

```sh
$ node build
$ open dist/index.html # open works on macOS, simply double-clicking the file on Windows/macOS works
```

**If you make changes to anything in `calc/`, you must run `node build` from the top level to
compile the files and copy them into `dist/` again. If you make changes to the HTML or JavaScript in
`src/`you must run `node build view` before the changes will become visible in your browser**
(`node build` also works, but it is slower, as it will compile `calc/` as well, which is
unnecessary if you did not make any changes to that directory).

Before opening up a Pull Request, please ensure `npm test` passes:

```sh
$ npm test
```

### Import

This repository also houses an internal package under `import/` which is used for populating the
Pokémon sets data (as well as data about random battle options) used by the UI. Before making
changes here you must run `npm install` from under the `import/` directory to install its
dependencies as they are not installed by default. [`TASKS.md`][4] contains more information on
how to programmatically update sets.
